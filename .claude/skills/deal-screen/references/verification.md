# Verification standards (Stage 5)

Nothing proceeds without these. Automate the parsing, never the asking.

| Item | Acceptable evidence | Not acceptable |
|---|---|---|
| Revenue | Read-only processor access, Stripe export, live screen-share, TrustMRR profile | Seller-built spreadsheet, screenshots |
| Costs | Actual hosting/API invoices for 3 months | A single stated figure |
| Customers | Subscriber list count from the processor | The listing's metric box |
| Churn | A cohort table you build from processor data | The seller's stated rate |
| Traffic | GA guest access, Search Console access | Analytics screenshots |
| Domain | Whois history, archive.org | The seller's word |
| Backlinks | Ahrefs / Semrush — check for PBNs, spam, foreign-domain link farms | — |

## The three things to ask for first

Ask for these before anything else, in this order. They are cheap for an honest
seller and expensive for a dishonest one.

1. **Monthly revenue for the last 12 months** — a processor export or a
   screen-share of the Stripe dashboard. Say explicitly: *"I don't need a
   spreadsheet."* That sentence pre-empts the seller-authored document, which is
   the artefact most likely to be wrong.
2. **Active paying subscribers, and the subscription/one-off split.** The split
   is where pay-once revenue hides inside a "SaaS" listing.
3. **Where the last 20 customers came from.** Harder to fabricate than any
   aggregate, and it is the real answer to the channel question.

## Reconciliation

Every number the seller gave must agree with its primary source. Build the table
in the diligence pack and fill the right-hand column from the source, not from
the conversation.

**Any single unexplained discrepancy resets the deal to Stage 3.** Not "note it
and continue". The rule exists because the first discrepancy is never the only
one — it is the one that happened to be checkable.

## Refusal

Ask once, plainly:

> Is there a reason you'd rather not share processor data directly?

Legitimate reasons exist — an employer, a co-founder, a nervous first-time
seller who wants an NDA. Those are answerable. "It's all in the spreadsheet"
is not a reason, it is a decline, and the deal stops there.
